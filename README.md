# DSH 投研资料库

这是面向 macOS 的本地插件包：用自己的研究笔记和获授权的星球帖子作为对话证据，可以按引用回到当时版本。包内不含任何个人数据库、凭据或预载资料。没有星球账号也能使用；不声明 Windows 支持。

## 在另一台 Mac 上试用

1. 安装 DeepSeek Harness（开发时对接的版本 `0.2.2-rc.5`），并确认 DSH 运行环境能找到 `python3`。需要 Python 3.9+ 及带 FTS5 trigram 的 SQLite。插件没有第三方 Python 依赖，不要求 uv、npm 或模型密钥。可先在本机终端运行 `python3 --version`；首次建库还会检查 SQLite 所需功能。
2. 解开分发包，把包含 `package.json` 的整个目录保存在固定位置。打开 DSH 的「插件 → 添加插件」，选择这个本地目录。开发者也可以直接选择本仓库；不要选择知识库数据目录。
3. 在「插件」页打开「投研资料库」，选一个独立空目录建库。预览并导入一份笔记，然后在新对话里问「在我的投研资料库中找……，请给出原句和引用」。不使用模型也可以在管理页检索。卸载不删除库，重新安装后可选回原目录。
4. 干净机器验收：不带旧项目或任何数据库，按上述步骤试用；更新笔记后确认旧引用仍可读，再用清理功能验证刷新不复活。记录 macOS、DSH、Python 与 SQLite 版本。开发机上把包解到空目录不等同于完成此项。

### 当前实现状态

已在本机 DSH（`0.2.2-rc.5`）安装并激活：插件行无告警，对话工具 `investment_kb_query` 已注册且能返回库状态，管理界面已注册到插件的设置插槽。管理页上的浏览器→Host 调用需在已登录的页面里点击才会发生，本会话没有浏览器控制，因此那条往返链路尚未实测；界面外观、系统文件选择器和真实星球授权同样待验收。

插件通过 DSH 的远程端点（命名空间 `investmentKb`，方法 `manage`）向管理页暴露操作，对话侧只暴露只读工具；两者共用同一套 Python 核心与库。

### 从源码试跑本地核心

在本项目目录运行以下命令。这个里程碑只用 Python 3.9+ 标准库，其 SQLite 需支持 FTS5 trigram，不需要安装第三方包。开发机验证环境：macOS 26.6.2 arm64、Python 3.9.6、SQLite 3.51.0；这不替代另一台干净机器的安装验收。下面的建库路径请换成独立空目录，笔记路径换成自己的文件：

```sh
python3 kb_cli.py --library ~/投研试用库 init
python3 kb_cli.py --library ~/投研试用库 import-file ~/Documents/跟踪笔记.md
python3 kb_cli.py --library ~/投研试用库 search '光模块'
python3 kb_cli.py --library ~/投研试用库 read '把搜索结果的 citation 粘贴在这里'
python3 -m unittest discover -v
```

再次导入同一路径会检查更新；内容未变就跳过，改变后保存新版本。搜索默认只看各资料最新版本；旧 citation 在重新启动后仍能回读。原件以内容哈希去重，原始字节和检索段落目前一起保存在 SQLite 中。支持 UTF-8 / 带 BOM 的 UTF-16 文本、Markdown、HTML 和 DOCX，单文件上限 8 MiB。在 macOS 上还可以预览或刷新整个目录：

```sh
python3 kb_cli.py --library ~/投研试用库 preview-folder ~/Documents/研究笔记
python3 kb_cli.py --library ~/投研试用库 refresh-folder ~/Documents/研究笔记
python3 kb_cli.py --library ~/投研试用库 sources
```

预览不登记来源。刷新会登记来源，并逐项报告新增、变化、未变、忽略、不支持或失败。文件从原目录移走不影响已归档版本。命令 `remove-doc SOURCE KEY`、`remove-source SOURCE`、`clear` 分别删除资料、来源或清空库，都必须额外传 `--confirm` 才会执行。`SOURCE`、`KEY` 可直接取搜索结果中的 `source`、`key`。普通刷新不会复活已删资料；明确执行 `restore-doc SOURCE KEY --confirm` 后再刷新才会重新导入，旧引用不会指向新资料。这是应用层清理，不是对系统备份的安全擦除。

### 手动同步已获授权的知识星球

在自己的本机终端运行，下列 `123456` 替换为数字星球 ID。首次同步会提示输入 token（不回显），不读取旧项目配置，不应将 token 放入命令参数或聊天。非交互调用可由启动进程提供 `ZSXQ_ACCESS_TOKEN`。只在显式执行同步时请求星球，不在查询时联网。

```sh
python3 kb_cli.py --library ~/投研试用库 sync-planet 123456 --max-pages 1
python3 kb_cli.py --library ~/投研试用库 planet-status 123456
python3 kb_cli.py --library ~/投研试用库 search '光模块' --source 'zsxq:123456'
python3 kb_cli.py --library ~/投研试用库 document '上一步返回的 citation'
```

保留信息流返回的帖子／问答正文和必要元数据。内嵌文章目前只归档返回的标题，不代表已采集文章全文；不下载附件，不调用模型结构化；状态里的已见最早／最晚日期不是“中间每一天均已采全”的证明。`document` 返回引用对应版本的有序段落，即使之后更新了资料也不会切换版本。采集器使用离线模拟响应验证，真实账号联网效果和 DSH 界面仍待验收。以下为完整首版目标，不代表已全部交付。

## 从空环境开始

前置条件允许包括 DSH、Python 和 uv。发布时须在插件说明中列出实测版本、安装与检查步骤；依赖缺失时提示如何修复。插件应携带自身所需的 Python 源码和依赖声明，以锁定的依赖建立自己的环境，不引用开发者机器的工作路径。首次运行选择独立空目录，新建本地库。不读旧项目的数据库、配置或凭据，也不继承旧定时任务。

## 用户路径

1. 选择本地单文件或登记文件夹，预览新增、变更、重复和不支持项，再导入。文件夹支持手动一键刷新，不监听后台变化。支持 Markdown、TXT、DOCX 和保存的 HTML；引用定位到标题、小节、段落或表格位置，不承诺 Word 页码。HTML 从磁盘解析，不加载外部资源。
2. 知识星球是可选内置来源。用用户自己的授权手动抓取，复用原项目适用的抓取、去重和断点逻辑，但写入新库。记录原文、来源、帖子 ID、作者、发布时间、原帖链接、采集时间和同步状态。凭据不写进资料库、日志、版本库或模型上下文。
3. 入库全程脚本处理，不需要模型密钥、向量模型或云端抽取。不做观点结构化、摘要或实体标注。基础检索使用本地全文索引，需用中文问题实测召回，不把关键词检索称作语义搜索。
4. 对话可跨来源检索或限定来源。默认返回带前后文的相关片段，按需读取指定版本的原文；两者均可发给当前对话模型。引用区分资料来源，显示可得日期和定位信息；没有发布日期时不拿采集时间冒充。资料不全或同步失败时显示实际覆盖情况。

## 存储与组件边界

插件包、用户原始目录、知识库目录三者分离。DSH 界面处理来源登记、导入预览、刷新状态、证据查看及清理确认；Host 将业务操作交给随包提供的 Python 核心，对话检索和界面查看共用同一套查询逻辑。管理操作走所有者浏览器专用 RPC；对话工具 `investment_kb_query` 只能查询当前已选库，无权切库、导入、同步或清理。

SQLite 保存来源、来源内标识、文档版本、正文片段及定位、同步进度和忽略记录；原件快照按内容去重。检索索引是可重建的派生数据。文档身份与快照内容分开：不同来源的相同内容可以共享快照，但必须保留各自出处。刷新不修改原文件；改版后旧引用仍指向旧版本。源文件移走或删除不自动清除归档。卸载插件不删除资料库。

## 清理语义

- **删除选中资料**：确认后删除该资料的全部版本、正文、索引和无人引用的快照。保留最小的来源内忽略标识，不保留正文，以防普通刷新又导入；用户可明确重新导入。
- **移除来源及其资料**：解除登记并清理该来源的资料，不影响其他来源的引用或共享快照。
- **清空当前库**：明确展示目标库与影响范围，确认后清除归档、索引、同步与忽略记录并解除所有来源登记。三个操作都不修改原文件或远端帖子。
- 已清理的引用显示不可用，不重定向到其他版本。清库不能撤回已经进入对话历史的文字。

## 发布验收与边界

自动化回归覆盖四种本地格式、中文检索、目录刷新、历史引用、清理、模拟星球分页及跨来源证据。分发测试会在新的 HOME 与 npm 缓存中实际打包，逐项核对归档清单，再从解包目录建立独立知识库，用包内 Host 回读原句。它不会使用开发仓库中的 Python 核心或读取旧资料库，但仍与开发机共用操作系统和解释器。真实授权星球、另一台 macOS，以及界面的实际显示与系统选择器交互，需要分别验收。

| 场景 | 通过标准 |
|---|---|
| 干净 macOS | 在没有旧项目、旧数据库、旧凭据和预热依赖缓存的新用户环境或干净机器上，按公开说明从插件包安装并建库；记录系统、DSH、Python、uv 版本与执行结果。仅在开发机创建空库不算通过。 |
| 无账号本地使用 | 不配置星球、模型密钥也能导入四种格式并本地查到中文原句；重复刷新不产生重复版本；更新后新旧引用可分别核对。 |
| 新星球来源 | 使用新配置从零抓取；重复抓取不重复入库。失败可见且可续跑，不把未覆盖时间段说成无资料。 |
| 对话取证 | 在同一次回答中分别引用一条星球原文与一段本地资料，两处都能回读对应版本；可仅查某一来源。 |
| 清理 | 验证三种粒度、取消确认、同内容跨来源引用、清理后的引用提示、普通刷新不复活和显式重新导入；验证所有原文件未改动。 |

## 版本管理

Git 仅跟踪插件源码、依赖声明、设计和脱敏测试样本；开发数据、凭据、个人资料和原始参考对话不提交。按可验证功能分次提交，不默认推送远端。

实施顺序：先验证独立建库、本地中文检索及版本回读；再接入四种本地格式、刷新与清理；随后适配星球抓取与 DSH 界面和对话工具；最后打包并完成干净环境验收。
